# Agent 工作台与真实调度改造

日期：2026-09-14。范围：画布右侧 Agent、后台 Agent 配置 / 技能绑定 / 记忆配置 / 调度记录。保留橙色品牌与黑灰色界面，不安装或替换为 OpenClaw。

## 原因与对应改动

| 原问题 | 本次处理 |
| --- | --- |
| 预设卡片不等于实际数据库配置 | 后台关系图来自真实 Agent 行，按 deploy_key / parent_deploy_key 展示主子关系；可直接编辑实际记录。没有记录时不展示假预设实例。 |
| 子 Agent 工具只返回配置，没有执行 | 按已启用的直接子级生成委派工具，实际调用模型，独立上下文，结果返回主 Agent，并持久化开始 / 配置 / 工具 / 结束事件。 |
| 温度、输出上限只保存在表单 | 传到每次模型调用；温度 0 不再被后台改成 1；模型名称与实际模型 ID 分开处理。 |
| 公共 Agent 接口没有返回调度关系 | 返回部署标识、父级标识与模型 ID，画布默认选择主 Agent，不再误选最后一个子 Agent。 |
| 重启会重新覆盖 Agent 及技能预设 | 初始化只补齐缺失项，已有模型、提示词、启停、父子关系、技能正文与绑定不被覆盖。 |
| 绑定的旧 Markdown 技能被标为 code，执行时不支持 | 仅将带指定套件来源、纯 content_md 的旧知识文档作为只读方法论；没有开启任意代码执行。中文技能工具名加唯一 ID，避免撞名。 |
| 记忆表单有未接入的参数 | 只编辑实际生效的最近对话轮数、关键词检索上限；向量模型和自动摘要标为“未接入”，保留旧值兼容但不假装使用。 |
| 停止按钮只是断开显示 | 调用服务端取消接口。排队任务直接取消；执行中任务先保留会话占用，执行器感知停止后落终态。 |

## 工作方式

采用 agent-builder 的小型执行循环思路：主 Agent 理解目标并选择必要工具，避免每轮机械运行全部角色。参考 OpenClaw 的会话串行和隔离子任务概念，落实在已有 Go / React / PostgreSQL / Asynq 中，不引入另一个网关。

```text
画布提交 → 持久化任务 → 会话队列 → 读取本次生效配置
                                   ↓
                           主 Agent 的模型 / 工具循环
                           ├─ 只读方法论与隔离记忆
                           ├─ 按需委派子 Agent → 独立文本结果
                           └─ 画布操作建议 → 生成媒体由用户确认
                                   ↓
                         保存会话 → 终态与可回放事件
                                   ↓
                         画布 SSE / 后台调度台
```

- 同一会话按创建顺序执行；数据库事务锁用于跨执行器领取，不会在模型调用期间长时间占用事务。不同会话可以并行。
- Asynq 遇到同一会话忙时延迟重试，不耗尽任务失败重试次数，也不占着执行器等待。无 Redis 的进程内模式有 10 分钟排队等待上限；生产仍应使用 Redis。
- 主任务最长 10 分钟、最多 12 轮工具循环；每个主任务最多调用 4 次子任务，每次最长 2 分钟、6 轮工具循环，子任务目前串行调用。
- 子任务只获得明确传入的任务上下文，不继承整段主会话；只允许读取方法论技能，不直接操作画布、调用 HTTP / 代码技能或递归派生。需要澄清或执行时交回主 Agent。
- 支持“子 Agent 继承主模型”和“子 Agent 独立模型”。单次对话的模型选择覆盖主任务模型；继承模式下子任务也使用这次选择。每个任务保存实际模型与配置模型，避免把覆盖后的模型混同于后台默认值。
- 会话历史按用户轮次裁剪，而非简单取固定消息行数。关键词记忆在数据库中先匹配再限制条数，按用户、Agent、项目 / 工作区隔离；目前不是向量检索或自动摘要。
- 断线重连只读持久化事件，不重新提交模型任务。已开始的任务被重复投递时不会再次执行工具；超过有效执行期限的旧占用在下一次领取该会话时标为中断，不自动重放。
- 对话消息按事务保存；审计写入失败会停止继续执行工具。取消不会撤销已经完成的外部操作，也不承诺撤销供应商已接收的请求或费用。
- 画布生成操作保留人工确认。确认动作移到 React 状态更新函数外，并防止同一确认卡重复触发，避免开发模式重放状态更新造成重复提交。

## 页面

- `/app`：图三方向的黑灰悬浮侧栏、顶部主 Agent / 新建 / 历史、底部用户欢迎语、三个真实技能入口、圆角输入框、模型与手动确认。保留现有画布节点，不为截图清空用户内容。
- `/admin/agents`：实际主子关系、模型、启停、技能绑定与编辑。子 Agent 编辑仅列出可调用的只读方法论。
- `/admin/memory`：真正生效的两项记忆限制；恢复默认不会删除记忆。
- `/admin/agent-runs`：最近 200 个真实主任务，每 3 秒同步；搜索、状态筛选、任务详情、历史生效配置、主子任务及时间线。
- 历史 `request_payload = {}` 的未闭合任务不计入当前运行数，不改写或删除原记录。没有历史配置快照的任务明确说明缺失，不用当前配置代替。
- 调度事件接口只公开结构字段；隐藏工具参数、结果正文、模型思考和密钥。管理员原有权限范围内仍可查看任务输入及最终回复。

## 接口兼容

继续使用持久任务接口 `POST /api/app/agents/{id}/jobs` 与事件回放接口。新增 `POST /api/app/agent-jobs/{id}/cancel` 和管理员事件查询 `GET /api/admin/agent-runs/{id}/events?after=...`。

旧的直接执行入口 `POST /api/app/agents/{id}/run` 返回 410，提示迁移到任务接口，避免绕过会话排队、取消和审计。项目现有前端已使用任务接口；外部旧客户端需要迁移。本次不需要新增数据库迁移。

## 明确边界 / 后续

- 这不是完整移植 OpenClaw：不包含跨设备网关、定时心跳、跨会话自主通信、子任务并行调度、向量记忆或自动压缩。
- 子 Agent 当前是隔离文本顾问；外部生成仍由主 Agent 提议并由用户在画布确认。任务中止不会自动回滚已完成的外部操作。
- 后台呈现的是已配置模型和实际运行快照，不保证每个供应商当前都可用；需要有效的渠道、凭据及工具调用能力。缺少配置时应纠正模型渠道，不编造成功或偷偷切换账号。
- 本地 HTTP 开多个带事件流的验证标签可能占满浏览器连接数；验收已关闭额外的画布 / 试衣验证标签。生产部署建议 HTTP/2，后续可做跨标签事件复用。
