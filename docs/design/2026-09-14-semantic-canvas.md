# 主 Agent 与语义画布控制

日期：2026-09-14

## 本次结果

用户只面对一个主 Agent，不需要从生产、剧本、通用及其重复条目中选择。主 Agent 根据任务决定直接完成，或通过一个 `delegate_agent` 工具请求已启用且有权限访问的专业顾问。后台保留配置入口和真实子任务事件，不删除已有配置、历史对话或运行记录。

采用 agent-builder 的最小化能力设计：模型决定做什么，工具负责可靠执行；没有引入固定的多层审批/决策流程，也没有安装 OpenClaw 或其他 Agent 框架。

## 不让模型反复算坐标

底层画布仍有坐标，这是渲染必需的数据；变化是坐标留在执行层，不再默认写进每轮模型提示词。请求开始时携带已有画布快照，模型只看到有界的节点名称、ID、内容摘要及连线关系。

可以直接表达：

- “把图片放在这个文本右边”：`create_node` / `move_node` 使用 `placement.anchor_id` 和 `relation`。
- “把这 10 个分镜排成两行”：`layout_nodes` 使用 `mode: grid, columns: 5`。
- “按文本 → 图片 → 视频的连接关系整理”：`layout_nodes` 使用 `mode: flow`。
- “在这个分组下面继续”：已有分组 ID 也可以作为摆放参照。

普通问候不要求读画布、不主动列功能清单或汇报坐标。工具返回节点 ID、版本及执行结果，供后续操作直接使用。需要具体内容、目标不明或发生冲突时仍可按需查询，不能承诺永不读取状态。旧会话中的原始回复不做修改，新规则作用于后续请求。

## 当前算法

1. 尺寸优先使用浏览器传来的 `measured`，其次显式宽高；未测量的新节点按节点类型、文本框尺寸、媒体比例预留尺寸。
2. 相对放置先计算参照节点/已有分组的包围盒，再沿保持上下/左右关系的方向扫描障碍，跳到障碍边界之外。
3. 横排、竖排和网格按节点各自尺寸与间距计算。
4. 流程布局使用确定性的拓扑分层；有环时明确返回网格降级标记，不改动连线。
5. 批量布局把所选节点看成一个整体避让未选节点，单批最多 200 个；不改内容、不增删连线。

这是轻量级拓扑分层和矩形避让，不是 ELK，也没有完整的交叉边最小化或端口路由。复杂、大规模流程后续可接入 [ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)；[React Flow 官方布局说明](https://reactflow.dev/learn/layouting/layouting)也介绍了 Dagre、ELK 等方案。当前方案不引入额外依赖。

## 冲突和权限

- 执行层检查目标存在、锁定状态、输入合法性和预期版本；整批验证后才发出一次 `move_nodes` 建议。
- 前端先校验所有目标及 `from_position`，再一次性应用位置变更。目标被删除、锁定或手动移动时，整批拒绝，保留用户修改。
- 单节点移动也携带原位置用于冲突检查。拒绝操作不会推进本地任务版本或显示“已排列”；后续依赖旧状态的操作也会因版本不符被拒绝。
- 后台记录工具执行、子任务起止、耗时、用量及画布操作建议；画布建议不等于浏览器应用成功。当前没有浏览器确认回执协议。
- 专业顾问仍为隔离的文本子任务：不能直接写画布、调用付费媒体、执行 HTTP/代码技能或递归委派；主 Agent 审核结果后统一执行。每个主任务最多 4 次委派，子任务最多 6 步、2 分钟。
- 媒体生成仍需用户确认；单主 Agent 不意味着取消权限、预算或确认边界。

## 已知边界

- 服务端持有请求时的快照及本任务内变更，不是持续同步整个协作画布；没有新增全量 CRDT 或双向增量同步。
- 新节点、内容增长和媒体加载后的尺寸可能变化，未测量时使用预估；下一次请求携带新测量值可重新整理。当前不提供内容变化后的持续自动重排。
- 布局冲突会在客户端明确报错，不会静默覆盖手工移动；主模型暂时没有收到客户端应用失败的回执。
- 默认主入口优先选启用的 `productionAgent`，其次 `universalAi`，最后稳定选择一个启用的顶层 Agent；没有可用项时显示真实配置错误。后台仍可管理专业 Agent。
- 没有新增自动删除、后台无限循环、任意系统操作或自动消费权限。

## 验证

- 后端全量 `go test ./...` 通过，API 可执行文件构建通过。
- 前端 TypeScript 检查通过；主入口、流式事件、布局活动、画布状态和后台展示相关 83 项测试通过。
- 测试覆盖负坐标、大尺寸、100 个密集节点、拓扑排序、环降级、锁定、删除、版本冲突、手动移动，以及统一委派工具的目标检查。
- 已在实际画布页面确认“主 Agent · 按需调度”，不再出现 Agent 下拉选择；没有在用户画布发起收费模型请求或修改节点做验收。

- `src/app/components/agent/canvas-layout-patch.ts`：全批次位置前置校验。
- `backend/internal/skills/application/agent_dispatch.go`：统一专业顾问选择工具。
- `backend/internal/skills/interfaces/agent_delegation.go`：真实子任务、权限与预算。
- `backend/internal/skills/application/canvas_semantic_layout.go`：语义摆放、尺寸和布局算法。
- `backend/internal/skills/application/tools.go`：语义画布摘要与交互约束。
