# H3 音画分采 8 步

## 范围

画布模型 `minimax-h3-t2v-ref2v-turbo-local` 的质量档新增 **音画分采8步**。旧极速/官方8步不改默认；导演台模型不改。音画分采是新生成路径，不是旧视频自动修音，也不能保证无杂音。

发布状态：已完成代码、前端构建与独立后端实际生成测试，已导出 ComfyUI API 工作流。正式 9090/9091/9092 后端仍在处理用户任务，尚未更换可执行文件或应用迁移 051，因此正式画布的新档位尚未发布。临时测试后端 9093 已优雅关闭。不要在有运行/排队任务时直接重启生产实例。

## 实际接线

1. 音频阶段：现有完整 Ref2VA 模型，不挂 Turbo LoRA；32×32 低空间 latent，视频/音频 shift 12/3，Euler + simple，20 步。与最终视频使用相同帧数和参考条件。
2. 视觉阶段：现有金鱼兼容官方8步路径，Turbo LoRA 0.75、Euler + beta、8 步。取第一阶段音频 latent，独立设 mask=0；视频 mask=1，进行视觉采样。
3. 最终视频拼接第一阶段解码的原音，同时另存 FLAC。环境声与对白一起保留，不做整轨静音。

使用原生 `LTXVSeparateAVLatent`、`SetLatentNoiseMask`、`LTXVConcatAVLatent`。虽然节点名有 LTXV，其实现支持 H3 AV latent。音频长度必须匹配，否则补齐尾段会恢复去噪。

原有「均衡二采/高质二采」也改为锁住首轮音频，二次采样只增强画面，最终音频来自首轮。此改动不涉及导演台的独立采样路径。

这是基于现有权重的轻量两阶段变体，不是完全照搬 [CornyShed 两阶段工作流](https://huggingface.co/CornyShed/ComfyUI-workflows/resolve/main/MiniMax/H3/two-stage/minimax-h3_tia2v_two-stage_cornyshed.json)。没有新增 FL2VA 大模型加载；低空间音频阶段仍会处理参考条件，多张大参考图可能拖慢速度。

## 使用与审核

对有对白的短镜头先试新档位。台词、环境声、配乐各自明确；没有配乐写 `non_diegetic_music: N/A`，不要把环境声一起删除。固定一项参数做对比，保留旧版。

音画审核为旁路标记；解码/ASR/响度不代替听审。出现问题先定位生成音频、二次采样、解码或拼接阶段。修复需用户确认，保留原音与原片；该选项不会重跑历史镜头。
