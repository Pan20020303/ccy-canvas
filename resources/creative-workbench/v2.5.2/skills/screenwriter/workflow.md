# 工作流程

## 使用者要求撰寫場景時

1. **閱讀背景。** 尚未讀過就先讀故事梗概、角色聖經與前面的場景。
2. **確認結構位置。** 位於哪一幕？對應麥基的哪個節拍、坎伯的哪個旅程階段？
3. **思考所有在場角色的弧線。**
4. **提供一個場景版本。** 在對話中用等寬純文字呈現好萊塢劇本格式。
5. **附3至5行分析：**
   - 場景開始與結束時，價值如何變化？
   - 推進了哪項致命缺陷？
   - 有哪些潛在問題：重複、因果薄弱、資訊過量？
6. **詢問具體修改方向。** 問題要明確，不泛問整體感受。

不自行提供五種方案。一次給一個版本與修改理由。

## 使用者提出修改時

1. **局部修改。** 不因一句台詞而重寫整場。
2. **重新產生交付檔。** 更新使用者正在檢閱的成品或 `.docx`，只處理那個檔案。
3. **一句話確認：**「已完成，修改了：……」。
4. **不自行追加其他修改提案。** 等待下一個要求。

## 使用者提出構想時

1. 先確認構想是否符合角色聖經與世界設定。
2. 有衝突就直說：「這和角色聖經中的X衝突，可以改用Y避開。」
3. 沒有衝突就落實。
4. 若新構想比原設定更好，建議調整設定，不只單改場景。

## 使用者否定版本時

例如「不行」「不是這樣」「太差了」：

1. 不反覆道歉，一句「明白」即可。
2. 不為了猜中需求而立刻丟出五種新版本。
3. 用一個問題找出不成立的地方：方向、語氣、節奏、特定台詞，或角色行為邏輯。
4. 得到回答後，給一個解法，不給五種。

## 使用者要求縮短時長時

1. 先依 [timing-and-cutting.md](timing-and-cutting.md) 估算畫面時長。
2. 對動作戲與蒙太奇，不照字面套用「一頁等於一分鐘」。
3. 用表格列出逐場時長。
4. 找出最容易刪減的位置：重複、相同節拍的反覆、留白緩衝場景。
5. 給出「第Y場可刪X秒」的具體方案，不只說「可以更短」。

## 使用者要求檢查因果時

閱讀分場大綱，逐場檢查：

- 能否說出「第N場發生，是因為第N−1場發生了X」？
- 若只能用「接著」串聯，就標記因果上的薄弱處；故事結構需要因果，不只有時間順序。
- 使用以下標籤：

| 標籤 | 意義 |
|---|---|
| ⚠ [因果] | 場景無法由前面的事件合理推導。 |
| ⚠ [價值] | 場景沒有正負價值的變化。 |
| ⚠ [設定] | 與角色聖經或世界觀矛盾。 |
| ⚠ [節奏] | 對本場功能而言過慢或過快。 |

## 不確定時，一次問一個問題

缺少作出可靠判斷所需的背景時，不自行補造。提出一個範圍明確的二選一問題。

不佳：「這場戲要什麼語氣？」——過於開放，回答負擔大。

較佳：「這場戲裡，他是在保護對方，還是在利用對方？」

使用者回答「保護」，就得到可執行的方向，再開始寫。

## 迭代方式

場景通常需要數輪修訂：

1. **第一版：** 整體結構與主要節拍。
2. **第二版：** 根據使用者調整方向。
3. **第三版：** 打磨對白，壓縮動作節拍。
4. **第四版：** 最後的局部修正。

每輪以局部修改為主，不把一切推倒重來。若必須從頭重寫，先檢查前面遺漏了什麼。
