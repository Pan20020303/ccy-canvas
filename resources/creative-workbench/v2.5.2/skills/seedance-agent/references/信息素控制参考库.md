# 信息素控制参考库

> **来源**：电影叙事学中的信息密度理论
> **用途**：确保每一秒画面都充满有效信息，杜绝观众出戏的冗余时刻

---

## 核心概念

影片的每一秒都在和观众的注意力博弈：
- 给冗余信息 → 观众出戏
- 给密集但无意义的信息 → 观众疲劳
- 给精准锚定的信息 → 观众被牢牢抓住

**信息素 = 画面 + 声音 + 台词 + 情绪变化中观众获得的新认知**

---

## 一、信息锚点系统（每镜 ≥ 2个锚点）

### 五种信息锚点类型

| 锚点类型 | 定义 | 判断标准 | 嵌入描述示例 |
|---------|------|---------|-------------|
| **视觉揭示** (V) | 展示了一个之前没出现过的东西 | 观众看到了新东西 | `窗外一枚核弹正在落下` |
| **情绪变化** (E) | 角色情绪状态发生改变 | 表情/身体动作有明显变化 | `眉头从紧皱变成松弛` / `嘴角从微笑变成抿直` |
| **关系位移** (R) | 两个角色之间距离/权力/信任发生变化 | A 靠近 B / B 退后 / 谁掌权变了 | `他后退一步` / `她把手从他手臂上移开` |
| **空间认知** (S) | 观众对空间的认知被刷新 | 空间本身的尺度/位置/功能被揭示 | `拉远后才发现房间只是巨大建筑中的一格` |
| **预期颠覆** (P) | 观众以为会发生但没发生，或反着来 | 打破已有预期 | `观众以为他要拥抱她，但他只是擦肩而过` |

### 强制规则

1. **每个镜头最少嵌入 2 类信息锚点**。单一锚点（如纯展示环境）只在建立镜头中允许。
2. **相邻镜头不能使用完全相同类型组合**。如镜1=V+S，镜2必须至少换一类（如V+E或E+R）。
3. **建立镜头豁免**：仅限全段第1镜或新场景第1镜，可用单一S锚点。

### 锚点注入方式

锚点通过**动作、对白、构图、音效**注入，而非直接描述。

❌ 直接写：`这个镜头展示了角色的孤独`
✅ 锚点注入：`角色站在巨大落地窗前 + 他的身影只占画面1/10（S锚点） + 他抬手想碰玻璃然后放下（E锚点）`

## 二、信息冗余杀灭

### 三层去冗余规则

**规则 1：视听不重复**

| 重复类型 | ❌ 冗余 | ✅ 优化 |
|---------|--------|--------|
| 画面+台词重复 | 画面：角色在哭 / 台词："我好难过" | 画面：角色在哭 / 台词："我去给你倒杯水"（用行为回避情绪） |
| 画面+音效重复 | 画面：门关上 / 音效：关门声 | 保留音效，画面转向另一个信息锚点 |
| 台词+台词重复 | 前一句已说X，后一句又说X | 后一句替换为观众不知道的新信息 |

**规则 2：动作去冗余**

每个动作链条最多保留 3 个关键节点。多余节点 → 切镜跳过去。

❌ `走向门口 + 伸手碰门把 + 转动门把 + 拉开门 + 跨过门槛 + 转身关门 + 手从门把上松开`
✅ `走向门口（镜头1）→ 手碰门把（镜头1）→ [切] → 他在门外的走廊里（镜头2，剩余步骤被跳过）`

**规则 3：音效去冗余**

事件音效不超过 3-4 个/镜头。超过则合并或删除。

## 三、延迟揭示（每场景 ≥ 1次）

### 三种延迟方式

| 方式 | 操作 | 效果 | 示例 |
|------|------|------|------|
| **视觉延迟** | 先不让观众看到关键物体，用遮挡/浅景深/机位隐瞒 | 悬念累积，揭示时冲击力翻倍 | 角色盯着画面外某处看了 3 秒，第 4 秒镜头才摇过去 |
| **信息延迟** | 观众和角色同时知道/角色先知道观众不知道 | 好奇心驱动观看 | 角色收到纸条，表情变了，观众不知道纸条写了什么，直到 2 个镜头后 |
| **因果延迟** | 先展示结果，后揭示原因 | 倒叙制造困惑然后痛快解释 | 先看到角色满手是血站在洗手间，3 个镜头后回溯发生了什么 |

### 强制规则

每个场景至少包含 **1 次延迟揭示**。

## 四、信息密度曲线

### 每镜信息密度审计

生成后对每个镜头评估信息密度：

| 密度等级 | 信息锚点数量 | 评价 | 处理 |
|---------|------------|------|------|
| **过低** | 0-1 个 | 🔴 观众必然出戏 | 必须增加至少 1 个新锚点 |
| **正常** | 2-3 个 | 🟢 合格 | 无需调整 |
| **密集** | 4+ 个 | 🟡 可能过载 | 考虑拆分到下一个镜头 |

### 全段信息密度曲线

理想曲线应该呈现 **波浪式起伏**：

```
密度
 ↑
 │  ████                ████
 │  ████  ████  ████  ████
 │  ████  ████  ████  ████  ██
 │  ████  ████  ████  ████  ██
 └──────────────────────────────→ 时间
   建立   发展   高潮前  高潮  释放
   (2-3)  (2-3)  (3-4)  (4+)(1-2)
```

**密度分配原则**：
- 建立段：2-3 个锚点/镜 —— 让观众舒适进入
- 发展段：2-3 个锚点/镜 —— 稳定信息流
- 高潮前：3-4 个锚点/镜 —— 加速信息密度
- 高潮段：4+ 个锚点/镜 —— 顶峰冲击
- 释放段：1-2 个锚点/镜 —— 给观众消化时间

## 五、协同模式建议（Agent 主动优化用户画面设计）

> 当用户提供的画面设计存在信息素问题时，Agent 不应沉默执行，而应**礼貌地给出专业建议**。

### 建议框架

```
⚠️ 导演建议：[具体问题描述]
   → 当前：[用户的设计]
   → 建议：[优化方案]
   → 理由：[影视原理]
   → 是否采用？如不采用，我将按你的原设计继续。
```

### 触发建议的条件

| 检测到的问题 | 建议内容 |
|------------|---------|
| 画面+台词说同一件事 | "画面已经展示了[情绪]，台词如果在此时给一个新信息，张力会更强" |
| 一个镜头只有一个信息锚点 | "这个镜头只有[锚点类型]，可以考虑在动作中增加一个[建议的锚点类型]" |
| 连续两个镜头没有新信息注入 | "镜N和镜N+1的信息有些重复，是否考虑在镜N+1中展示[建议的新信息]？" |
| 缺少延迟揭示 | "这个场景可以设计一个延迟揭示——比如先不让观众看到[关键物体]，积攒悬念后在[时机]揭示" |

## 六、嵌入格式

### 自检清单（生成后执行）

```
□ 【信息锚点】每个镜头是否包含 ≥2 类信息锚点？标注类型（V/E/R/S/P）
□ 【信息冗余】画面+台词是否说同一件事？动作链条是否超过3个关键节点？
□ 【延迟揭示】本场景是否包含 ≥1 次延迟揭示？
□ 【密度曲线】全段信息密度是否符合波浪式起伏？有没有持续低密度段？
```

### 协同模式建议格式

```
⚠️ 导演建议（可选）：
[具体问题 + 建议方案 + 理由]
是否采用？如不采用，按原设计继续。
```

---

## 七、核心原则总结

1. **每镜 ≥ 2 锚点**：单一信息锚点只在建立镜头中豁免
2. **视听不重复**：画面+台词/画面+音效不能说同一件事
3. **每场景 ≥ 1 延迟揭示**：悬念是观众的肾上腺素
4. **密度波浪曲线**：建立(2-3)→发展(2-3)→高潮(4+)→释放(1-2)
5. **协同模式给建议**：Agent 发现信息素问题应礼貌建议，但不强制修改
