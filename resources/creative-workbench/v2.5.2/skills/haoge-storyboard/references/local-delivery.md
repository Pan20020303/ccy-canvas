# 本地Markdown交付规范

本文件是`haoge-storyboard`本地备份的唯一权威规则。所有制作制式和交付去向均必须执行；用户不需要另行提出“保存文件”。

## 一、保存时机

- 每个通过内容核验的完整成品或完整批次，在聊天宣布完成前写入本地文档。
- 长文本分批时，每次只在完整场景、情节节点或集末完成当前批次后保存，不把半句对白或未完成场次写进文件。
- 聊天正文和文件正文必须来自同一份定稿内容，不分别生成两份可能漂移的版本。

## 二、目录优先级

按以下顺序选择目标目录，不为已有答案重复询问用户：

1. 用户本轮明确指定的输出目录。
2. 稳定本地源文件的父目录，例如用户提供的`C:\项目\原稿.md`所在目录。
3. 当前工作区根目录。

系统临时目录、剪贴板缓存、浏览器下载缓存和应用附件缓存不视为稳定源目录。来源仅为粘贴文本或临时附件时，使用当前工作区根目录。目标目录不可写时，尝试当前工作区根目录作为一次后备；仍失败则报告实际错误和目标路径，不得声称已经保存。

## 三、文件名

默认格式：

```text
{项目名}_分镜剧本_{制式}_{交付去向}.md
```

制式使用`16x9横屏精品剧`或`9x16竖屏短剧`；交付去向使用`AI导演接力版`或`完整执行分镜版`。项目名优先使用源文件名去扩展名，其次使用已确认作品名，仍未知时使用`未命名项目`。

删除Windows文件名禁止字符`< > : " / \ | ? *`和控制字符，去掉末尾空格与句点。不得直接使用源文件原名覆盖源文件。

若目标文件已存在：

- 同一项目的后续新批次，继续维护已确认的同一累计文档。
- 修改已经保存的正文或重新生成整部作品时，不覆盖旧版本；依次创建`_V2`、`_V3`等新文件。
- 无法确定现有文件是否属于同一项目进度时，优先创建新版本，不冒险覆盖。

## 四、文档内容

本地文件使用UTF-8编码和原生Markdown结构，至少包含：

```markdown
# 作品名

- 制作制式：16:9横屏中长精品剧 / 9:16竖屏系列短剧
- 交付去向：AI导演接力版 / 完整执行分镜版
- 当前范围：完整作品 / 第X集 / 第X批（覆盖节点……）

正文……
```

文件正文保留作品/集标题、场次、动作、对白、声音和交付模式要求的全部字段。不要把整篇正文放进最外层代码围栏；不要写入聊天中的选择菜单、进度催问、自检草稿、解释性前言或联系方式。

## 五、分批与修订

- 分批交付时，本地累计文档必须包含从项目起点到当前批次的全部已完成内容，并在标题层级上保持连续。
- 追加新批次前先读取已有文件结尾，防止重复场次、跳号或把内容插入错误位置。
- 用户只修改未保存的新批次时，可在写入前直接修正；用户修改已保存内容时，建立下一个版本文件，并把已确认旧内容与修订内容合并成新的完整累计稿。
- 不把验收失败、尚待确认或明显截断的正文写进正式备份。

## 六、写入后验证与回报

写入后必须重新读取目标文件并确认：

1. 文件存在且不是空文件。
2. UTF-8中文可正常读取。
3. 文件标题、制作制式和交付去向正确。
4. 首个已完成场次与最后一个已完成场次都存在。
5. 聊天正文中的当前交付范围没有在文件中缺失。

最终回复使用可点击的绝对路径链接，例如：

```markdown
本地备份：[雪夜困兽_分镜剧本_16x9横屏精品剧_AI导演接力版.md](C:/项目/雪夜困兽_分镜剧本_16x9横屏精品剧_AI导演接力版.md)
```

路径包含空格时按宿主要求使用尖括号包裹链接目标。未完成写入后验证前，不得报告保存成功。
